# 计算逻辑参考

本文档描述引擎（`src/engine/`）的全部计算逻辑。所有金额单位为元，利率为小数，模拟为逐月推进。公式正确性由 `src/engine/__tests__/` 中的单测锁定（手工案例精确到分 + 性质测试双重校验）。

## 1. 总体模型

- **逐月循环**：对每个方案、每种情形（预期/压力），从起点月推演到统一终点 H
- **统一终点 H** = max(全部贷款按原计划还清所需月数, 公积金处理时点+1, 退休年偏移, 自定义终点年, 最晚事件月+1, 12)，上限 600 个月。**所有方案必须模拟到同一 H 才可比**
- **双情形**：预期情形用各理财池的「预期年化收益」；压力情形改用「预期 − 最大亏损」。贷款、收支、公积金在两种情形下完全一致
- **方案结构**：公共参数（贷款/收支/账户/人生事件）+ 各自的提前还款事件集；`scenarios[0]` 恒为基准「完全不提前还款」

## 2. 贷款数学（`loan.ts`）

记 `i = 年利率/12`（月利率）、`B` 剩余本金、`n` 剩余期数。

### 等额本息（annuity）

```
月供 M = B · i · (1+i)^n / ((1+i)^n − 1)      （i=0 时 M = B/n）
每月：利息 = B · i；本金 = M − 利息；B ← B − 本金
```

### 等额本金（linear）

```
每月固定还本 p = P/N；利息 = B · i；月供 = p + 利息（逐月递减）
```

### 尾差处理

任一步后 `|余额| < 0.005` 元即置零结清；末期实付 = 余下本金 + 当期利息，余额绝不穿负。

### 放款延迟

`startDelayMonths > 0` 的贷款（如 2020 开始模拟、2021 才买的车贷）在放款前：不计月供、不计入负债与净资产、不参与利率重锚；还清时间从放款后起算。

### 利率路径

执行利率 = 「当前执行利率」或「生效年份最新的一条规则指定的绝对利率」，按 `floor(m/12)` 对应的年序生效。利率变化当月对在还贷款重锚：等额本息按「期限不变」用新利率反算新月供；等额本金天然自适应（利息按余额计算）。

## 3. 提前还款重算（核心正确性）

设还款后余额 `B'`、原月供 `M`、原每月本金 `p`：

| 还款方式 | 效果 | 算法 |
|---|---|---|
| 等额本息 | 缩短期限 | 实数解 `n′ = −ln(1−B′·i/M)/ln(1+i)` → 四舍五入取整 → 用整数期反算新月供 |
| 等额本息 | 减少月供 | 期限不变，`M′ = annuityPayment(B′, i, n′)` |
| 等额本金 | 缩短期限 | p 不变，`n′ = ceil(B′/p)` |
| 等额本金 | 减少月供 | 终点不变，`p′ = B′/n′` |

护栏与规则：
- `B′·i ≥ M`（月供不够付息）时缩期限无解 → 自动回退「减少月供」并告警
- 还款额以当前剩余本金封顶，超出部分不扣（银行口径）
- 违约金 = 已执行额 × 违约金率，从资金来源额外扣收，不冲本金
- 同月多条还款段按序执行，后者看到前者重算后的状态

## 4. 目标解析与公积金限制

目标解析优先级：`targetLoanId` 指定 > `targetGroup='housing'`（作为「还房贷」，房贷内部自动挑当前利率最高的一笔）> 来源约束自动（公积金来源只在房贷中挑；现金/理财来源在全贷款中挑）。

**公积金只作用于房贷**：不能用于车贷等其他贷款的月冲或提前还款，违规组合会被跳过并产生预警。

## 5. 单月资金路由流水线（顺序不可变）

```
① 利率更新（放款后的贷款套用新利率并重锚）
② 收入入账：工资/12 进活钱；年终奖按发放月进活钱；公积金缴存进公积金账户
③ 刚性支出记账：生活支出（可选通胀递增）+ 固定支出（先记账不扣）
④ 贷款计划供款：
   totalDue   = Σ 在还贷款的当月应还
   housingDue = 其中房贷部分
   fundOffset = min(公积金余额, housingDue)   —— 仅当「公积金月冲」开关开启
   差额 = totalDue − fundOffset 由活钱支付
⑤ 月供缺口补足：若 活钱 < 生活+固定+自付月供 合计，
   按 monthlyTopUpSource 从理财池支取补足：
   - 'wealth-proportional' 全部池按余额比例支取
   - 某池 id                只从该池支取
   - 'cash-only'           不补（活钱透支 → 断裂检测接管）
⑥⑦ 大额收入入账 / 大额支出扣款（大额支出不能用公积金）
⑧ 提前还款段（见 §3）
⑨ 定投：只动用「活钱 − 应急底线」以上的部分，不足自动降挡
⑩ 收益滚存：各理财池 ×(1+r/12)；公积金 ×(1+计息率/12)；活钱不计息
⑪ 公积金到期处理：可提取时点 = 退休年 ?? 缴存结束；
   hold 继续计息 / lumpPrepay 一次性冲抵房贷 / withdrawToWealth 转入指定理财池
⑫ 快照：净资产 = 活钱 + Σ理财池 + 公积金 − 贷款余额（不含房产）
⑬ 断裂检测：活钱 < 0 即断裂；连续段只记一次预警
```

关键顺序约定：公积金月冲（④）先于公积金一次性冲抵（⑪）；收入先于支出；同月多条事件按「收入<支出<还款<定投」优先级 + id 稳定排序。通胀指数锚定**模拟起点年** `(1+g)^年序`。

## 6. 应急活钱底线

`emergencyReserve`（默认 10 万）始终留在活钱里：**定投与现金类提前还款不可动用**（不足则自动降挡）；生活开销、月供与大额支出可以动用。缺口补足（§5-⑤）发生在活钱耗尽之后。

## 7. 指标口径（`metrics.ts`）

- **名义少付利息** = 基准总利息 − 方案总利息（大众口径，忽略机会成本）
- **真实节省** = 方案期末净资产 − 基准期末净资产（机会成本口径，科学结论以此为准）
- 两者都展示；0% 理财收益时两者相等，收益越高差距越大
- 还清时间：每笔贷款首次余额归零的月份（要求已放款）

## 8. 存款宽心指数（`score.ts`）

覆盖月数：`coverage(m) = (活钱 + Σ理财池) / 当月经常性流出(m)`，经常性流出 = 生活+固定+自付月供（**不含**大额支出——一次性存量消耗不是燃烧率；公积金用途受限也不计入流动资产）。开销为 0 视为充裕（封顶 600 月）。

分段映射（c = 覆盖月数）：

```
c ≥ 36   → 80 + min(20, (c−36)/24×20)     安稳
12 ≤ c<36 → 50 + (c−12)/24×30            舒适
6 ≤ c<12  → 25 + (c−6)/6×25              焦虑
c < 6    → c/6 × 25                       危险
```

综合分 = `0.20×当前跑道 + 0.35×最危险时刻(预期) + 0.30×最危险时刻(压力) + 0.15×断裂惩罚(100−断裂月数×15)`，四舍五入。

硬帽：预期情形发生断裂 ≤ 24 分（危险）；仅压力情形断裂 ≤ 39 分（焦虑）。

带位：≥80 安稳 ｜ 60–79 舒适 ｜ 40–59 紧张 ｜ 25–39 焦虑 ｜ <25 危险。

## 9. 盈亏平衡扫描（`breakeven.ts`）

找理财收益率 r* 使 `f(r) = NW_方案(r,H) − NW_基准(r,H) = 0`：

1. 粗扫 r ∈ [0%, 10%]，步长 0.25%（41 次全量模拟）；扫描时覆写全部池收益率、关闭压力
2. 相邻符号相反的区间做 12 轮二分
3. f(r) 不保证单调 → 报告**全部**穿越点；仅一个时结论卡才给出确定的临界值

## 10. 关键节点推导（`milestones.ts`）

从聚焦方案的预期情形快照与预警中提取：活钱跌破应急底线、活钱清零、开始花理财补缺口、资金断裂、房贷/其他贷款还清、公积金停止缴存与到期处理、退休、相邻收入段年收入降幅 >25% 的断崖。按时间排序输出到时间轴。

## 11. 明确的简化

- 净资产为金融口径，**不含房产市值**（对所有方案同值，不影响对比结论；卖房用「大额收入事件」建模）
- 收入一律视为税后到手，不做税务计算
- 利率重定价按年简化；违约金为简单比例；不考虑银行最低还款额等约束
- 断裂后不冻结贷款：允许现金持续为负继续模拟（保证方案间记账规则一致），负值可视作未建模的应急借款
