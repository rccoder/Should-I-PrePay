# 需求演化与设计决策记录

本文档记录项目从构想到定稿的完整需求演化过程与每个关键决策的理由。市面房贷计算器很多，但都忽略了真实决策的复杂性——这些"被忽略的事"就是本项目的差异化价值。

## 一、用户原始需求（第一轮）

1. **提前还款不是一次性的**，可能分好几次 → 事件系统支持多条还款记录
2. **贷款利息会变**：前几年 6.x%，过几年 3.2% → 利率路径建模，允许大致设置
3. **商贷 vs 公积金贷**分开，提前还款对两者规则不同 → 两笔独立贷款建模
4. **公积金不能提取只能还贷**，但同时每月又能 cover 房贷 → 月冲模式 + 锁定资金逻辑
5. **可能有理财**，理财有收益 → 理财池 + 收益率
6. 核心输出：**会节省多少钱**
7. 应该是**可以拖动的东西**

## 二、讨论中补全的关键点

以下各条在需求讨论中逐步补充，均为市面工具普遍缺失的点：

### 决策正确性类
- **「省钱」的正确口径**：光看"少付利息"会误导，因为提前还款占用了本可理财的钱。科学口径是期末净资产对比。两个口径都要展示并解释区别
- **等额本息 vs 等额本金**：两者提前还款收益差异大，都要支持
- **缩短期限 vs 减少月供**：每次提前还款的独立选择，节省差异巨大
- **盈亏平衡分析**：理财收益率达到多少时提前还款不划算（临界收益率），比给结论更有洞察
- **LPR 重定价机制**：利率不是随便变的，建模为「当前利率 + 未来 LPR 变动预期」，而非凭空分段填数

### 公积金深度建模（本项目最大差异化）
- **公积金持续缴存流入**：不只现有余额，每月还在往里流钱；缴存额可按年度区间变化
- **锁定资金的机会成本≈0**：公积金余额不能取出来投资，所以应优先烧公积金余额做提前还款，不动自己能投资的钱——市面工具基本不算这笔账
- **缴存结束的处理**：离职/退休销户时余额一次性可拿，提供选项（躺平计息/一次性冲抵/取出进理财）

### 人生现金流维度（工具从"省息计算器"升级为"人生现金流模拟器"）
- **收支时间线非线性**：用户按年份段编辑收入/支出预期，支持**收入断崖**（失业/裸辞/退休）
- **存款消耗场景**：某年后收入大降就靠存款过日子，存款会减少；无法覆盖开销+房贷 = 资金断裂红色警报
- **支出三分法**：房贷月供（引擎算）+ 固定支出（物业费/车位/保险等多条命名）+ 动态生活支出；均按年段编辑
- **年终奖/年度性奖金**：中国收入结构核心组成，只填月薪会低估可投资资金 20–50%
- **通胀**：30 年视角按今天物价算生活支出完全失真，可选通胀率自动递增（默认 2.5%）
- **退休金**：收入断崖≠零收入，退休后有养老金；提供退休快捷模板
- **大额事件型支出/收入**：买车/装修/育儿/教育/医疗、卖房/理赔/继承——人生现金流的最大坑，结构上与提前还款事件统一
- **贷款通用化**：不止商贷+公积金两笔，贷款列表可加车贷等

### 安全性维度
- **存款宽心指数**（用户提出"宽心指数"概念）：钱多安稳、钱少焦虑，量化为 0–100 综合分（安全跑道/最危险时刻/断裂惩罚），每个方案各自一个分数——直观展示"省利息是用安全感换的"
- **理财压力测试**：预期年化是乐观估计，实际可能亏损。用户配置最大亏损%，引擎用「预期−最大亏损」重跑悲观情形，若悲观情形资金链断裂要提前预警

### 资金分层（用户明确：手上有存款不代表都在理财里)
- **活钱**（活期）：日常开销+月供从这里出，收益≈0
- **理财池 × N**：初始只有部分存款进理财，之后靠**年度定投**滚入；每池有独立预期收益和最大亏损（高风险/低风险预设）
- **定投可持续性校验**：到时点活钱不够则警告并按实际能投的算

## 三、交互决策

- 用户要求「可以拖动的东西」→ 确认为**两者都要**：
  1. 参数滑块实时联动（拖动毫秒级重算刷新图表）
  2. 时间轴拖拽编辑事件（拖动改时间点、编辑金额、增删）——统一事件系统使所有人生事件都能在同一条时间轴上编辑
- **多方案并排对比** + 预设快捷模板 + localStorage 自动保存防丢（用户原话："每个输入啥的都保存到 localstorage，防止丢失"）

## 四、已定设计决策（不要轻易更改）

| 决策 | 内容 | Why |
|---|---|---|
| 输入按年、引擎按月 | 收支年薪/年额输入，÷12 摊入每月 | 人的心智模型是年薪；贷款天然逐月；年内发钱时点对30年结论是噪声 |
| 统一事件系统 | 提前还款/大额收支/定投都是 discriminated union 的 SimEvent | 结构统一后时间轴拖拽天然覆盖所有事件类型 |
| 同一终点 H 对比 | 所有方案一律模拟到 H=max(还清月,退休年,最晚事件月) | 「真实节省=净资产差」可比的前提；先还清的靠理财滚存正是机会成本含义 |
| 断裂继续模拟 | 允许现金为负，不冻结贷款 | 冻结会让不同方案断裂后记账规则不同，破坏对比 |
| 净资产不含房产 | UI 注明 | 自住房不卖不影响差值 |
| 双情形模拟 | 预期收益 + 压力(预期−最大亏损) | 基准情形安全≠真安全 |

## 五、明确不做（避免过度设计）

- 税务计算 —— 统一「税后到手」口径，UI 提示
- 房价波动 —— 自住房不卖不影响还贷决策；卖房场景用大额收入事件覆盖
- 保险精算、精确重定价日、银行违约金细则 —— 简化或用事件拼
- 房租 vs 买房对比 —— 用户已购房，超出定位

## 六、技术选型记录

- 用户指定：shadcn/ui 样式；纯前端零服务端（"整个架构不需要 server，纯前端 + 前端存储即可"）；Vite+React+TS
- 推论选型：Recharts（shadcn Charts 同源风格一致）、zustand persist、zod 校验 localStorage 数据、vitest 引擎单测
